# Research to PKM

Convert sources into durable knowledge without collapsing evidence, interpretation, and synthesis into one layer. Lock the kernel contract before creating or rewriting notes.

## Define the research output

Identify the question, intended decision or artifact, acceptable source types, time horizon, and desired depth. Decide whether the vault needs:

- A source note that preserves one source's claims and metadata.
- Atomic concept notes that express reusable ideas.
- A synthesis note that compares several sources.
- A map of content that provides navigation.
- A project note that turns findings into actions.

Create only the layers that serve the request. Place them with the locked folders, note types, and property schema. Do not start a parallel research taxonomy.

## Capture provenance

Match an existing source-note template. If none exists, use a minimal schema such as:

```yaml
---
type: source
title: Source title
authors: []
published:
accessed: YYYY-MM-DD
url:
tags: []
status: processed
---
```

Record stable identifiers such as DOI, ISBN, or canonical URL when available. Keep quotes distinguishable from paraphrases and retain page, section, timestamp, or locator information. Never fabricate missing metadata.

## Process a source

1. Preserve bibliographic facts and the source's scope.
2. Extract claims relevant to the research question.
3. Separate direct evidence, the source author's interpretation, and your synthesis.
4. Record uncertainty, limitations, conflicts of interest, and meaningful disagreement.
5. Link claims to existing concepts and projects only when the relationship is substantive.
6. Consider a separate concept note when it has independent value and serves the request. Do not make atomic-note creation mandatory. For parse intake, substantive development and integration follow its explicitly enabled options.

Prefer concise paraphrase. Use direct quotations sparingly and preserve exact attribution.

## Create atomic notes

- Give each note one durable idea, question, model, or distinction.
- Use a title that states the idea rather than merely naming the source.
- Explain the idea in context, link supporting source notes, and connect related or contrasting concepts.
- Do not split material so aggressively that each note loses explanatory value.
- Avoid creating duplicate concepts under slightly different titles; search first and merge deliberately.

## Synthesize

Organize synthesis around claims or questions, not a source-by-source procession. For each conclusion:

- State the conclusion and confidence.
- Link supporting and contradicting source notes.
- Explain why the evidence supports the conclusion.
- Identify unresolved questions and the next useful research step.

Use a Canvas only when spatial relationships materially aid understanding. Use a Base when property-driven filtering, sorting, or grouping improves retrieval.

## Intake from external material

- For web pages, PDFs, transcripts, or messages, retain the original location and access date.
- For PDFs, preserve page references and distinguish OCR uncertainty.
- For transcripts, preserve speaker and timestamp when relevant.
- For imported notes, keep an untouched source copy or import boundary until normalization is verified.
- Do not send private vault content to an external research or AI service without explicit permission.

## Validate

Check that every important factual claim can be traced to a source note or is clearly labeled as synthesis. Check that links resolve, titles are not duplicated, property types match the vault, and the resulting notes answer the original research question.
