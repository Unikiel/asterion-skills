# Explore an entire channel or playlist

The default scope is all discoverable videos, with best-effort knowledge extraction from each accessible item. There is no three-video, 60-minute, or generic page-budget ceiling on this scope. Batches are execution units; completing a batch does not complete the request. Sample only when the user explicitly asks for a sample or narrower set.

## Discover and preserve the inventory

Inspect the channel's available Videos, Shorts, and Streams/archive surfaces and relevant playlists. For a supplied playlist, enumerate its entries in order. Follow pagination or continuation cursors to the end through available public tools; preserve enumeration progress when interrupted. A first screen, search results, or a tool's top-N response cannot establish the full catalog. Check whether the tool silently truncates. Record each surface inspected, access date, pagination endpoint/cursor or last processed position, and evidence that enumeration ended. Mark discovery partial when completeness cannot be established. Retain visible unavailable/deleted/private entries with their reason; never guess hidden video IDs or bypass access controls. List unidentifiable unavailable slots in the discovery note.

Deduplicate repeated appearances using stable video IDs (watch, Shorts, live, and share URLs may identify the same video). Preserve playlist order/membership in working notes when it adds meaning; avoid researching duplicate appearances twice. For a channel, distinguish the creator's uploads from other creators' videos in curated playlists. The latter are supporting leads, not additional channel uploads unless requested. Record any unavailable catalog surfaces as discovery gaps.

Create a durable report JSON outside the vault in an established task workspace. Use the `collection` schema in [explore-capture.md](explore-capture.md) as the inventory and checkpoint, retaining stable source IDs. Record its absolute path and the next discovery/extraction step in `resume_note`. Keep detailed per-video working summaries and evidence locators alongside it if needed; include their paths in the checkpoint. Do not rely on conversation memory or a temporary browser session alone. Add newly discovered items as pending without resetting existing progress.

## Work through every item

Process pending items in manageable batches, choosing order for useful prerequisites, chronology, or the user's focus. Continue through subsequent batches while tools and execution capacity allow. For each video, attempt full speech/text extraction and inspect relevant visual explanations, following [explore-media.md](explore-media.md). Preserve substantive concepts, mechanisms, examples, evidence, caveats, and timestamped references in a cited per-video section, even when several videos overlap. Build cross-video synthesis from these sections without discarding unique lessons.

Checkpoint after each batch and before context/turn boundaries. Save through a sibling temporary file and atomic replace; retain the previous valid checkpoint until the replacement validates. A discovered URL is pending, metadata alone is not knowledge extraction, partial media coverage stays partial, and a blocked item records the attempted methods and reason. Try available alternative extraction methods when they can improve coverage. Missing backends do not justify skipping the remaining videos. Avoid retrying an unchanged access failure indefinitely; record a useful retry condition and continue other items.

The ordinary page/search guidance governs prioritization of supporting research, not collection enumeration or video processing. Do not stop because three videos seem representative, the topic repeats, or the first batch used a nominal budget. Stop only at completion, an explicit user limit, or a concrete access/tool/execution constraint. If interrupted, preserve all pending entries and the exact next action. Do not create a scheduler, recurring automation, or promise unattended continuation.

## Resume and deliver

Before treating a URL as already captured, inspect its earlier coverage and checkpoint. Resume an unfinished collection from durable state under the existing request; do not ask permission for each batch. Preserve completed evidence, retry partial/unavailable items when another method or changed access offers progress, and continue incomplete discovery. If the checkpoint is missing, reconstruct what is supported by the previous note and re-enumerate to find remaining work; never assume the previous note covered the catalog.

Maintain one cumulative report during the run. Save a cited Markdown snapshot in existing intake at completion or a necessary pause; avoid creating a vault note for every execution batch. The existing writer is intentionally append-only: when a previous snapshot exists, use `--new-capture` for the resumed result, linking the older note without overwriting user edits. An unfinished snapshot is not a duplicate-research stopping condition. Ordinary completed-page duplicate behavior is unchanged.

Include per-video knowledge, cross-video synthesis, discovered/complete/partial/pending/unavailable counts, discovery evidence, and modality limitations. Counts must derive from the inventory. Report complete only when discovery is established and every inventory item is complete within the user's requested modality scope. If all accessible items have been attempted but some are inaccessible or partially inspected, say so and retain partial coverage. Distinguish this from a queue with pending work. Full-catalog discovery does not prove full media coverage or factual correctness.
